# retype 0.1.0 —— M0 地基

**这是一个里程碑版本，还不是可用的输入法。**

内核、词库、拼音解码、更新器都已经能跑，但**还不能在系统里打出中文**：
TSF 的组字串读写（`ITfEditSession`）是 M1 的工作。现在注册这个 DLL
不会吞掉你的按键（TIP 一律返回「不吃这个键」），但也打不出中文。

## 现在能做什么

下载 `retype-0.1.0-windows-x64.zip`，解压后：

```powershell
# 在终端里跑完整的输入链路（推荐，不需要安装任何东西）
.\retype-diag.exe --dict retype-dict.tsv

# 首刷延迟基准
.\retype-diag.exe --dict retype-dict.tsv --bench

# 排查候选排序：打印每条候选的逐边得分
.\retype-diag.exe --dict retype-dict.tsv --explain nihaomashijie

# 检查更新
.\retype-updater.exe check
```

`retype-diag` 的 REPL 里：输入拼音回车看候选，`1`~`9` 选词，
`:voice <文字>` 模拟一次完整的语音三段式流程，`:ctx <文字>` 设置上下文观察二刷重排，
`:help` 看全部命令。

## 本版本包含

**统一输入内核**（`core/engine`）
- 纯状态机 `Kernel`：不开线程、不做 IO，`handle(InputEvent) -> Vec<KernelAction>`
- 首刷（本地同步）/ 二刷（云端异步）编排，用 `gen` 代次丢弃过期结果
- 语音三段式状态机：interim → stable → final，松手后超时用 stable 兜底
- `LocalBackend`（去抖 worker 线程）+ `InlineBackend`（同步，供测试）

**本地拼音引擎**（`core/pinyin`）
- 421 个音节的音节表，已用 `pinyin` crate 的全量字音反查校验无缺项
- 词格 + k-best Viterbi，音节歧义交给词库解决（`xian` / `shanghai` / `jian`）
- 前缀候选：可以只选「你好」，剩下的 `mashijie` 继续组字

**词库**（`core/dict`）
- 349,045 词 → **352,357 条**已注音词条（含多音字变体）
- 系统词库 + 用户词库分层加权，选词/纠错/自造词/语音上屏都会回写学习
- `AsyncDict` 异步加载 + 单字降级：词库缺失也能打字

**云端抽象**（`core/cloud`）
- `CloudPinyin` / `LlmReranker` / `StreamingAsr` 三个 trait，本版本只提供 Mock
- 熔断器 + 超时 + 隐私闸门（上下文出网前强制脱敏）

**Windows TSF 骨架**（`platforms/windows/tsf`）
- 纯 Rust 实现的 `ITfTextInputProcessorEx` + `ITfKeyEventSink`，180KB DLL
- 影子模式（`RETYPE_TSF_SHADOW=1`）：喂内核但不吃按键，可在真实宿主进程里观察

**自动更新**（`core/updater` + `retype-updater.exe`）
- 查 GitHub `releases/latest`、语义化版本比较（含预发布）、按平台挑产物
- 下载后 **sha256 校验通过才落盘**，校验文件缺失则拒绝安装

| 指标 | 实测 | 预算 |

| 首刷按键延迟 P99 | 3.35 ms | 5 ms |

## 已知问题

- **TIP DLL 有 1,082 KB，太大了**。大头是 `pinyin` crate 内嵌的全量汉字→拼音数据
  （`retype-dict` 运行时要给用户自造词注音）。这个 DLL 会被注入到每个宿主进程，
  体积直接影响宿主启动速度。M1 会改成：构建期生成一张紧凑的「字→音节 id」表
  （约 30KB）随词库分发，用 cargo feature 把 `pinyin` crate 从 TIP 里摘掉。
- `woxiangchifan` 首选是「我**向**吃饭」而不是「我**想**吃饭」。
  unigram 模型无法靠上下文纠正，M2 的本地上下文打分 + M3 的云端重排解决。
- 打分靠 `word_bonus=3.5` 这个经验常数补偿 unigram 的 `−k·ln T` 偏差，
  M2 引入 bigram 后应退化成很小的微调量。
- 只有 x64 产物。32 位应用需要 x86 TIP，M1 补齐（CI 已在验证 x86 可编译）。
- 更新器只做到「下载 + 校验」，不替换 DLL —— TIP 被所有进程加载着，
  原子替换是 M5 安装器的工作。
- 云端能力只有 Mock，没有接任何真实供应商（ADR-0002 的刻意选择）。
