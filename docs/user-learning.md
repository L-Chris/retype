# 用户学习：持久化与跨应用共享

已实现持久化、跨应用共享，以及基于使用次数与近期偏好的排序。前后词搭配、导入导出及单词管理仍留在后续阶段。

## 数据与范围

- 正常上屏的候选选择保存在本机，跨应用共享；重新激活、退出应用、重启和升级后可恢复。
- 使用完整拼音与词语作为持久化主键，全拼和小鹤双拼共享记录；保留候选实际读音，不保存内部音节编号。
- 保存基础分数、累计选择次数、近期使用强度、活动序号、最后使用时间，以及已接入学习事件接口的自造词、纠错计数。不会保存按键日志或整份输入框内容。
- Windows 键盘输入目前产生候选选择事件。纠错和语音的存储接口已支持，但自动纠错采集、语音输入尚未接入生产输入流程。
- 英文按键统计属于独立的数量统计功能，本阶段不学习英文文本。
- TSF 仅在宿主明确提供 `TS_SS_NOHIDDENTEXT` 时允许学习，并在上屏时排除密码、私密和 PIN 输入范围。传统文本控件不提供输入范围时，以隐藏文本声明为判据；已提供的输入范围读取失败时不学习。必须成功写入宿主文档后才提交学习事件。
- v0.5.1 及以前只有会话内存记录，无法恢复之前已经退出的会话；新机制从安装后开始积累。

## 运行结构

```text
应用中的 TSF → 纯内存用户词库 → 异步学习队列
                                  ↓
                       retype-learning-host.exe
                                  ↓
              %LOCALAPPDATA%\retype\learning\user.db
                                  ↓
                    其他应用的后台缓存同步
```

每个宿主进程复用一份缓存及学习 worker；激活输入法不读数据库、不等待 IPC。内核与候选查询保留在应用内，无须迁移整个输入引擎。本地学习在 worker 更新后可用；其他应用约每秒同步一次。初次加载之前继续使用基础词库。

## 排序模型

生产学习器不再按候选位置添加固定分数。所有选词均记录一次观察；同一完整读音、相同输入覆盖范围的候选在解码后共同参与计算，包括词库词和多个词拼出的候选。不会为特定词、字母数或音节长度添加分数。

设原始候选路径分数为 s，组内总质量 M = Σexp(s)，基础条件概率 p₀ = exp(s)/M。个人证据 c = ln(1 + 累计次数) + 近期使用强度，调整后的条件概率为：

    p = (α × p₀ + c) / (α + Σc)
    调整分数 = ln(M) + ln(p)

保留 ln(M) 可避免直接用条件概率替换原路径分数后，破坏不同读音、不同长度候选之间的尺度。未涉及学习记录的读音保持原顺序与分数。新词的初始分数取实际词库分数，或复用现有分词路径分数；注册一个组合词不会凭空获得额外的词数补偿。

初始统一参数为 α=32，近期强度每经过 128 次新的词语学习活动减半；停机时间不影响它。累计次数完整保存，排序时取对数，让长期习惯有影响但不会无限累加阻碍新偏好。参数通过可复现的合成回放验证，尚未声称使用真实用户语料训练或获得某个准确率提升。

分段选词在最终上屏时一起记录；取消组字、退格恢复的选段不会写入学习。通过标点接受首选也计入观察。候选页面位置仅保留在兼容事件中，不参与打分。

数据库格式升级至 v2，保留 v1 的次数与确认序号，近期强度初始化为零，并重新解析基础分数，避免延续旧的饱和加分。协议保留 v1 管道与原字段，新增的统计快照为可选字段；完整的新排序需要应用加载新版输入组件。

后台进程按当前 Windows 用户独占管道，在用户登录时直接启动原生可执行文件；桌面客户端也能在断线时尝试启动。AppContainer 无须创建后台进程。SQLite 仅由该后台进程写入，同一账户的多个桌面会话共用这一写入者。

使用 `\\.\pipe\retype-learning-<用户 SID>-v1` 的原生 Win32 管道。真实 AppContainer 测试发现 `LOCAL\` 名称会被重定向到容器内部，不能连接桌面后台。管道允许低完整性和 AppContainer 客户端连接，读取请求后校验实际用户 SID；拒绝远程连接。客户端发送词语之前校验管道所有者，并且只允许身份级模拟；服务端恢复自身身份后才访问数据库。

数据库及备份目录的 DACL 仅授予当前用户与 SYSTEM 权限，不向所有应用包开放文件访问。测试使用临时 AppContainer 验证 IPC 可用，并确认实际数据库文件不可直接读取；真实 Windows 搜索框仍应在新安装包中做输入验收。

Windows 搜索等 AppContainer 宿主从输入法菜单打开设置时，也通过此管道转交桌面后台启动；设置进程不会继承搜索宿主的容器限制。请求仅包含固定操作和数值日志编号，不接受可执行文件路径或命令行。后台从当前安装目录启动设置，并将前台权限传给设置窗口。普通桌面宿主保留直接启动入口，所有启动和管道访问均在工作线程执行。

## 可靠性与升级

学习事件按客户端编号和连续序号提交，每批最多 128 条。分数、计数、确认序号和全局版本在同一 SQLite 事务中更新，提交完成后才确认。已保存但响应丢失的请求可以重放，不会重复学习。客户端从权威快照重建内存，并叠加仍待确认的事件；重建完成后一次发布，避免候选查询看到中间状态。

数据库使用 WAL 与 `synchronous=FULL`。正常写入每天至多更新一次一致性备份 `user.backup.db`。损坏数据库或较新的未知格式不会被自动清空；后台无法启动时，输入继续使用基础词库与当前缓存。备份恢复属于后续管理功能，当前不自动回退旧数据。

断线期间保留有界内存队列并自动重试。数据库已确认的事件不会因宿主退出丢失；退出前尚未确认的事件仍可能丢失。长时间故障导致队列满时记录警告并放弃后续学习，不能为了保存学习阻塞按键。

安装器把后台程序装入版本目录，同时更新用户登录启动入口。正在运行的后台检测 `ActiveDir` 变化后释放数据库与管道，再启动新后台；已加载的 TSF 客户端沿用 v1 协议重新连接。升级保留用户数据，卸载停用后台并沿用现有的“是否删除个人数据”选择。
