# 自动更新与版本目录安装

0.1.5 起，每次安装（包括同版本修复）写入 Program Files/retype/versions/<版本>-<安装标识>。
目录包含 x64/x86 DLL、更新器、更新脚本、词库及 installed.ini 哈希清单。
HKLM 64 位视图 Software\retype 的 ActiveDir、Version 指向当前安装，双架构 COM 注册指向新 DLL。
旧应用继续使用旧文件，新进程加载新路径。安装不关闭应用、不自动重启，不保证所有旧宿主立即切换。
旧目录保留到卸载，自动回收尚未实现。

旧平铺目录可迁移；但若仍有待重启替换任务，安装器要求先完成之前的重启，防止旧 RunOnce 注册覆盖新版。
安装失败时尝试恢复之前的双架构 COM 路径。

## 入口

语言栏右键和开始菜单提供更新窗口。retype-updater update 打开窗口；update --background 后台检查。
当前用户任务 retype-update-<SID> 登录两分钟后和每日触发，普通权限运行，不保存密码。
后台每 24 小时最多检查一次，可关闭或跳过版本；手动检查绕过限频。
后台只检查和提醒，不自动安装。每用户互斥量阻止重复更新。

## 流程

1. 独立 Rust 更新器查 GitHub 稳定版，比较 semver，不自动降级。
2. 窗口显示版本和说明链接，用户点击后下载；目标版本变化则拒绝继续并要求重新检查。
3. 安装包与 SHA256 文件须配对，URL 须为 HTTPS，文件名不得含路径分隔符。
4. 校验后写临时文件再改名，启动安装器前再次校验磁盘文件。
5. 安装请求 UAC，不关闭用户应用，不自动重启，保留日志。
6. 3010 记录等待重启；0 仍需校验目标版本、双架构 DLL 哈希、COM 路径及输入法名称。
7. 下次启动核验中断的安装状态，不把开始安装当作更新完成。

检查和下载通过异步子进程执行。下载阶段可关闭窗口取消，安装阶段禁止关闭窗口。
下载显示阶段进度，不显示虚假百分比。已有应用需重新打开才能加载新版。

## 状态与可信性

%LOCALAPPDATA%\retype\updates\state.json 原子保存开关、检查时间、跳过版本、安装目标和结果。
每次下载独立目录保存安装包与日志。不上传输入文本和词库。token 仅发送给 GitHub API 域名。
HTTPS + SHA256 是完整性检查，不等于发布者签名。当前没有证书，安装需要用户确认；
Authenticode 发布者验证仍待代码签名接入后实现。

## 验证

- test-update-state.ps1：限频、开关、状态原子持久化、损坏恢复。
- Rust 测试：已确认版本变化、路径穿越、HTTP 下载和校验文件错配均拒绝。
- test-upgrade.ps1：只允许干净 Windows Actions runner，安装已发布 0.1.4，保持旧 DLL 加载并升级，
  再保持新版 DLL 加载执行同版本修复；验证文件不被覆盖、注册可激活、后台任务存在并能退出。
- windows-update-tests.yml：测试分支或手动触发，不发布 Release。

GUI 的 DPI/主题、跨账户 UAC 及旧宿主长期持有 DLL 的兼容性仍需持续验收。
